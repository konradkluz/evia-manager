# Weryfikacja zbudowanego APK (`tools/mobile-apk/`)

EVM-009 AC5, AC6 (security-engineer B2, B3, B4). Używane przez job `mobile-apk` w `ci.yml`; działa **bez instalacji zależności** (tylko `node:*`). Sprawdza **gotowy plik**, nie źródła po `expo prebuild` — biblioteki dokładają uprawnienia i komponenty dopiero przy scalaniu manifestów. Odczyt przez `apkanalyzer` z Android SDK (`cmdline-tools/latest`), uruchamiany jako `java -classpath …` (bez powłoki i bez `.bat`).

| Polecenie                                                                                                                                                                                                                                                                               | Co robi                                                                                                                                                 |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `node tools/mobile-apk/cli.mjs verify --apk <plik> [--application-id <id>]`                                                                                                                                                                                                             | manifest, trzy zasoby XML i zawartość; kod 1 przy jakimkolwiek ustaleniu, wypisuje też SHA-256                                                          |
| `node tools/mobile-apk/cli.mjs digest --apk <plik> [--signed]`                                                                                                                                                                                                                          | SHA-256 pliku; w CI dopisuje podsumowanie do `$GITHUB_STEP_SUMMARY` (z napisem **NIEPODPISANY**, gdy bez `--signed`, oraz gałęzią i commitem przebiegu) |
| `node tools/mobile-apk/cli.mjs sign --apk <niepodpisany> --expect-sha256 <z podsumowania CI> --keystore <poza repo> --key-alias <alias> --out <plik> [--expected-cert-sha256 <odcisk>] [--ks-pass-env NAZWA] [--key-pass-env NAZWA] [--build-tools <wersja>] [--allow-placeholder-api]` | **podpis lokalny Konrada** (`src/sign.mjs`): patrz niżej                                                                                                |

## Co jest sprawdzane

- **Manifest** (`src/manifest.mjs`): `package`; uprawnienia dokładnie `INTERNET` + własne `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`; `targetSdkVersion` ≥ 34; `allowBackup=false`, `usesCleartextTraffic=false`, brak `debuggable`, obecne `networkSecurityConfig`, `dataExtractionRules`, `fullBackupContent`; `expo.modules.updates.ENABLED` nie jest `true`; brak komponentów expo-updates / dev-launcher / dev-menu; **jedyny wyeksportowany komponent lub komponent z filtrem intencji to `MainActivity`** z dokładnie jednym filtrem MAIN/LAUNCHER, bez linków głębokich.
- **Zasoby XML** (`src/resources.mjs`): sieć — `cleartextTrafficPermitted=false`, tylko magazyn systemowy (bez certyfikatów użytkownika), bez `domain-config` i `debug-overrides`; reguły kopii i przenoszenia wykluczają `root`, `file`, `database`, `sharedpref`, `external` i niczego nie włączają.
- **Zawartość** (`src/contents.mjs`): zakazane pliki (keystore, certyfikaty, `.env`, mapy źródeł, konta serwisowe) i wzorce poświadczeń w `assets/` (klucze prywatne, AWS, Google, GitHub, Slack, Stripe, JWT, hasło w adresie URL, przypisanie hasła); jedyną publiczną zmienną paczki jest `EXPO_PUBLIC_API_BASE_URL`; znacznik haków e2e (`E2E_HOOKS_MARKER`, `evia-e2e-hooks-panel` — EVM-093) w pakiecie JS lub zasobie to ustalenie, więc `sign` nigdy nie podpisze paczki z hakami (kontrola pozytywna: ten sam detektor na APK e2e musi znacznik znaleźć). Ustalenia podają ścieżkę i regułę, **nigdy dopasowanego tekstu**.

Fixture'y testów (`test/fixtures/`) to zapis wyjścia `apkanalyzer` dla prawdziwej paczki aplikacji (dane syntetyczne). Testy: `pnpm --filter @evia/mobile-apk run test:coverage` (próg 90%).

## Podpis lokalny (`sign`)

Wyłącznie na komputerze Konrada, z kluczem poza repozytorium; CI nie ma klucza (RR-21, ADR-0019). Kolejność: sprawdzenie wejścia (SHA-256 = `--expect-sha256`, brak podpisu, `verify`) → `zipalign -P 16 -f 4` → `java -jar apksigner.jar sign` (v2 i v3) → `verify --print-certs` → porównanie odcisku z `--expected-cert-sha256` / `EVIA_APK_CERT_SHA256` → ponowne `verify`. Narzędzia z najwyższej wersji `build-tools` w `ANDROID_HOME`, uruchamiane bez powłoki (`apksigner.bat` pomijamy: BatBadBut, CWE-78). Hasła: tylko `env:NAZWA` (domyślnie `EVIA_APK_KS_PASS`, `EVIA_APK_KEY_PASS`) albo prompt `apksigner` w terminalu; `pass:`, `file:` i hasło w argumentach są odrzucane (kod 2). Keystore w drzewie roboczym git (po `realpath`) → odmowa; ścieżka keystore'a nie jest wypisywana; wyjście narzędzi nie jest przekazywane, tylko kod i zredagowany komunikat. Procesy potomne dostają **listę dozwolonych zmiennych środowiska** (`src/env.mjs`: PATH, JAVA_HOME, ANDROID_HOME, katalogi tymczasowe i domowe), a zmienne z hasłami — **wyłącznie** `apksigner sign`; `git` jest uruchamiany ścieżką bezwzględną z PATH (nigdy z bieżącego folderu), `java` wymaga `JAVA_HOME`. `apksigner sign` dostaje jawnie `--v4-signing-enabled false` (bez pliku `.idsig`); `zipalign -P 16` wymaga `build-tools` ≥ 35.0.0 (czytelny komunikat z wersją znalezioną). Kod 128 z `git` to „nie jest repozytorium” tylko przy takim komunikacie; inne błędy (np. „dubious ownership”) → odmowa. Paczka z zastępczym adresem API CI (`api.example.invalid` w pakiecie JS) jest odrzucana, chyba że `--allow-placeholder-api` (wykrycie to dopasowanie tekstu w `assets/`; brak dopasowania nie dowodzi poprawnego adresu — kontrola ostrzeżeniem w podsumowaniu CI i w runbooku). Wynik: ścieżka, SHA-256 pliku, SHA-256 certyfikatu. Pełna procedura: `docs/ops/dystrybucja-apk-android.md`.
